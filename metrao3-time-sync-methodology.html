Metrao3 · Measurement methodology · Sheet TS-01

Time Sync for
Phase-Accurate
Transfer Curves

A transfer curve is only an impulse response if it carries phase. Phase is time — and in Metrao3 the microphones sit on n independent nodes, connected by whatever link each one happens to have: cloud, UMTS, LAN or Wi-Fi. The link carries the data. The time comes from somewhere else entirely: a GPS PPS clock at each node, and PTP across the LAN segment. This sheet shows what that timing plane actually delivers, and why the result is phase-accurate across the full audio band.

01

Phase is a time measurement, so a clock error is a phase error

architecture.md §6.3.5–6.3.6 · §6.3.8

Each receiver computes the transfer function against the reference by cross-spectral averaging, then inverse-transforms it. The impulse response is the transfer function. Discard phase and you do not get a worse impulse response — you get none at all.

Transfer function — Welch cross-spectral
H(f) = ΣGxy / ΣGxx
Complex. Accumulated over ~12 overlapping Hann frames per second. Bins more than 60 dB below the strongest are floored to zero.
Impulse response
h(t) = IFFT{ H(f) }
Requires the complex H. Magnitude-only data inverts to nothing physical — no arrival time, no reflections, no gate.
What a timing error costs
Δφ = 360° · f · Δt
Linear in frequency. 1 ms of clock error is 0.36° at 1 Hz and 3600° at 10 kHz — ten full cycles of ambiguity.
Coherence — the built-in referee
γ²(f) = |ΣGxy|² / (ΣGxx·ΣGyy)
An alignment that wanders between frames rotates the averaged cross-spectrum toward zero. Bad timing shows up here first.

Two distinct failure modes — only one of them is a clock problem

Ambiguity

Once the clock error passes half a period, the propagation delay you are trying to measure is indistinguishable from the clock offset. At 10 kHz a 1 ms error is 10 whole cycles — the phase reading is a number, but it means nothing.

Decorrelation

If the offset drifts across the twelve frames being averaged, each frame’s cross-spectrum vector points somewhere different and the sum partially cancels. Magnitude sags, coherence drops, and the result correctly reports itself as untrustworthy.

A static offset is not a failure mode. A constant delay is exactly the quantity the measurement exists to find: it is recovered by delay detection (§6.3.7), removed by circular-shifting the impulse response, and compensated in the spectrum by phase[i] += (2π · margin / N) · i. What must be controlled is not how large the offset is, but whether it is known and stable.

02

Any number of nodes, on any mix of links — because the link never carries the time

architecture.md §3–§4 · ADR-017 · ADR-001 (MQTT over WSS)

A session is one reference node plus n measurement nodes. Each node reaches the broker over whichever link it has — wired LAN, Wi-Fi, UMTS/LTE, or straight to the cloud — on one MQTT connection over WSS port 443, with CBOR payloads. Nodes do not have to agree on a transport, and adding the nth node does not tighten any requirement on the others.

That is only possible because Metrao3 runs two separate planes. The transport plane moves audio, results and settings, and is allowed to be slow, jittery and heterogeneous. The timing plane is what the phase actually rides on, and it does not touch the transport at all: a GPS PPS pulse into each GNSS-equipped node, and PTP from a GPS-disciplined master to the nodes sharing its LAN segment.

One session, n nodes, two planes

Above the nodes: where the time comes from. Below: where the data goes. A node’s position in one plane says nothing about its position in the other — a node on UMTS can be the best-timed node in the session.

n scales, the budget does not

Every node is disciplined to the same absolute reference — UTC via GNSS, or a GPS-disciplined PTP master. Error is node-to-UTC, so it never accumulates along a chain of nodes. Ten nodes are no harder to align than two.

Link quality ≠ time quality

A UMTS node with a GNSS fix is eligible for a phase measurement; a wired node without one may not be. All links terminate on the same broker and the same CBOR contract.

Eligibility, per node, per session

Each node advertises what it actually has. metrao3-cloud-api matches that against the use case’s threshold, so an n-node session can run mixed — loosely-timed nodes contributing magnitude and spatial context only.

03

The timing plane: a GPS PPS clock at the node, PTP across the segment

ADR-017 (supersedes ADR-004) · ADR-037 · architecture.md §5

Fine time comes from two mechanisms and only two: GPS PPS, which disciplines a node directly to UTC and needs no network at all, and PTP, which distributes a GPS-disciplined node’s time across its LAN segment. Underneath them sits coarse NTP, which every node always has and which is never asked to carry phase. Timing requirements belong to the use case, not to the node.

Fine time · absolute UTC · per node
GPS PPS clock

A discrete Quectel LC76G GNSS receiver on the cellular + GNSS daughter board. Its 1PPS pin is hard-wired to GPIO 17 — not multiplexed through UART or USB.

NMEA over I²C names the second; the pulse marks its exact edge.
Needs no LAN and no peers — which is what makes UMTS nodes first-class.
The PPS comes from the GNSS receiver, never from the modem: no mainstream cellular module has a timepulse pin (ADR-037).
Carries phase across the whole audio band.
Accuracy±1–5 µs
Fine time · local segment
PTP (Statime)

A GPS-equipped Metrao3 node becomes the PTP master for its segment and the other LAN nodes slave to it. Pure-Rust Statime — no grandmaster appliance enters the BOM.

Extends one GNSS fix to every wired node behind it — one antenna install covers the segment.
Disciplines a virtual clock (virtual-system-clock = true) so PTP and NTP never fight over CLOCK_REALTIME.
Software-timestamped on a Pi Zero 2 W — no PHC on the onboard MAC, so ~50 µs is the floor.
Carries phase to about 2.5 kHz.
Accuracy~50 µs
Coarse time · every node, always
Cloud / LAN NTP

Chrony against the Metrao3 NTP server with public-pool fallback, or against the reference node acting as LAN master. Rides the same WSS/443 path as the data.

Job: session windowing — which one-second blocks belong to the same measurement event. ~10 ms is enough.
Job: SPL and Leq integration, fleet logging, orchestration.
LAN master ±0.1–1 ms · internet ±1–20 ms · UMTS without a fix ±5–50 ms.
Never asked to carry phase.
Accuracy±0.1–50 ms
On the device: one chrony ladder, one owner of the clock chip
GPS / PPS→ NTP→ DS3231 RTC ±2 ppm ⇒ CLOCK_REALTIME

Timestamps come from CLOCK_REALTIME with no offline special-casing. hwclock’s own RTC sync is masked so chronyd is the sole writer to the chip. Chrony is configured to slew, never step, so a correction after an offline stretch can never delete or duplicate Leq data. The active source is published as the frozen enum clock_source: ntp | rtc | gps alongside clock_offset_us — an unrecognised refid yields nothing rather than a fabricated value.

What each path buys you, in degrees

Phase error against frequency, by timing path

Log–log, so every timing tier is a straight line. Read up from a frequency to find the phase error that tier leaves behind. Below 5° the phase is measurement-grade; above 180° the reading is ambiguous by at least half a cycle.

The ±1–5 µs GPS figure is the Raspberry Pi pps-gpio interrupt-latency floor, not a receiver spec: the LC76G’s own timepulse is two to three orders of magnitude better, which is why a timing-grade GNSS receiver would buy nothing here.

05

The decisive move: the reference signal carries the time, not the clock

ADR-017 §3 (primary path) · §4 (fallback) · architecture.md §6.3.7, §6.3.10

The transfer-curve protocol requires a known reference signal present in the captured data. Every measurement receiver decodes the reference stream, restores its amplitude and cross-correlates it against its own microphone capture; the exact start sample falls out of the correlation. Timing comes from the signal itself — which is how impulse-response measurement has always worked, and the only method that reaches genuinely sample-accurate alignment. It also inverts the requirement on the clocks: they need only be good enough to pick the right second.

Coarse from the clock, fine from the signal, residual from the impulse response

Three nested alignment stages. Each one is three to four orders of magnitude tighter than the one above it, and each is measured rather than assumed.

Delay detection is quality-gated

Prominence is the peak measured against the impulse-response noise floor, excluding ±5 samples around it. A transient spike cannot steal the lock.

Drift is absorbed, not fought

Crystal tolerance puts each node’s I²S sample rate a few ppm off 48 000 Hz. Over one accumulation window that is sub-sample, and the delay detector simply re-measures it every second. Over longer runs the sliding average tracks it. No explicit sample-rate correction exists, because none is needed.

When there is no reference signal

Some deployments cannot inject or capture one. Then a GPS-equipped Metrao3 node becomes the LAN PTP master and the others slave to it at ~50 µs — phase-accurate to about 2.5 kHz. This is the only retained role of Statime in the stack, and the sole reason PTP survives ADR-017 at all.

06

From aligned audio to a gated impulse response

architecture.md §6.3.3–§6.3.9 · metrao3-core::dsp

One pass per second on every measurement receiver. The four green steps are the ones that only exist because the phase survived — they are the payoff of everything above.

  1. Align
    Clock window, then correlation against the decoded reference
  2. Segment
    Ring buffer 4×FFT, 75% overlap, hop 4 096
  3. Window & FFT
    Hann periodic · 16 384 pt real→complex · 8 193 bins
  4. Cross-spectrum
    Gxy, Gxx, Gyy accumulated over ~12 frames
  5. H(f) & coherence
    Complex H = ΣGxy/ΣGxx · γ² gate at 0.2
  6. Inverse FFT
    Complex→real — this is the impulse response
  7. Detect & shift
    Direct arrival to a 10 ms margin, phase corrected
  8. Time gate
    Tukey, 0 → arrival + 8 ms · taper max(10%, 16 smp)
  9. Re-FFT & smooth
    1/12 octave, constant-Q energy average, 131 points
  10. Calibrate & publish
    Per-mic curve, then CBOR map + f32, NaN-native

The 8 ms gate is what separates the loudspeaker from the room: it keeps the direct sound and drops reflections beyond roughly 2.7 m of extra path. Gating is a time-domain operation on h(t) — and without valid phase there is no h(t) to gate.

07

The result declares its own timing quality

specs/cbor_schemas/tf-result.cddl · field-vocabulary.yaml · system-status.cddl

“Good enough” is not a claim the system makes once at design time and then assumes forever. Every published result carries the tier it was measured on, and the contract has a defined shape for the case where that tier cannot support phase.

timing_tier

A frozen enum on every transfer-function result: ntp_lan / ntp_internet / gps_pps. The consumer always knows which line of the chart above its data was measured on.

phase[] = NaN

When the tier cannot support phase accuracy, the phase array is filled with NaN — carried natively as f32, never a sentinel, never silently zeroed. Magnitude and coherence stay valid and present. The array is always there; its emptiness is explicit.

γ² < 0.2 → excluded

Coherence gating is independent of any declared tier. A misalignment nobody predicted still cancels the averaged cross-spectrum and drops coherence, and those bins leave the output. The system degrades loudly.

The same discipline runs on the health path: clock_source and clock_offset_us ride the status beat, so a node in GNSS holdover is visibly in holdover and is ruled out of a measurement that needs a live fix — decided at measurement time from published time quality, not from a profile baked in at install.

The conclusion

Time sync is good enough for a phase-accurate transfer curve — and therefore for a true impulse response — on both measurement paths, for n nodes on any mix of links.

Primary · ADR-017 §3

Reference signal present

Cross-correlation recovers the exact start sample from the audio itself, once every second. The clocks only have to identify the right window — about 10 ms of slack, which even internet NTP clears with room to spare. Alignment is sample-accurate, and the residual propagation delay is then measured out of the impulse response itself.

Phase valid: 20 Hz – 20 kHz, on any timing path including cloud NTP.
Fallback · ADR-017 §4

No reference signal available

Timing must then come from the clocks, so the clocks are made good enough for the job. A GPS-disciplined node holds ±1–5 µs to UTC — under 36° at 20 kHz, and under 2° at 1 kHz — with LAN PTP at ~50 µs as the segment-local tier beneath it.

Phase valid: whole band on GPS PPS; to ~2.5 kHz on LAN PTP.
Implementation status — stated plainly

This sheet documents the frozen design and the frozen wire contract. As of this revision mod-transfer-function is a lifecycle stub — the DSP pipeline it describes is specified and contract-bound but not yet running on devices — and the GPS/PPS rung of the chrony ladder is not shipped on any unit yet. The SPL and 1/3-octave paths, by contrast, are proven end-to-end on real Pi silicon.
